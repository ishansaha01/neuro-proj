# Roadmap

This file is the project's working plan and its record of every change. It has three parts:

1. **[Milestones](#1-milestones)**: what we are building, phase by phase, with checkboxes.
2. **[Design decisions](#2-design-decisions)**: numbered decisions (D-xxx), each with its reason and status. Change a decision by adding a new entry that supersedes the old one, not by editing history.
3. **[Change log](#3-change-log)**: one entry per change to the repo, newest first: what changed, why, and which files.

**Rules for every change**
- Each change gets a change-log entry here in the same commit.
- Each simulation output must be reproducible from `(config file, seed, code version)` alone.
- Each physical constant in the code names its source (paper, table, or "assumed, to verify").
- No hidden randomness: every random draw goes through the seed tree (D-004).

### Phase 1 — Ground-truth head *(Tue 17 Nov)*
Output: one HDF5/Zarr file per head holding 3D voxel maps on a common grid (default 0.5 mm isotropic), plus the config that made it.

- [x] **Anatomy (procedural):** nested ellipsoids for scalp, skull, CSF and brain. Smooth random deformation (Gaussian random field) of each surface, so every seed gives a different head shape. Skull thickness map with realistic regional variation, thinner at the temporal window.
- [x] **Skull microstructure:** three-layer skull (outer table, diploë, inner table). Porosity field φ(x) that is low in the tables and high in the diploë, with spatially correlated random texture.
- [x] **Material mapping:** derive every physical property from the microstructure (D-002):
  - acoustic: sound speed c, density ρ, attenuation α (porosity mixing law, Aubry et al., 2003);
  - X-ray: volume fractions of soft tissue, water and bone mineral → μ(E) (used in Phase 3).
  - Hidden variation: add a component of sound speed that the CT cannot see, tuned so CT explains about 23–53% of sound-speed variance (Webb et al., 2018). This is what makes the CT an *imperfect* prior.
- [x] **CBV ground truth:** baseline vascular density map (higher in grey matter); a target region (default: a cortical patch, analogous to the parietal/motor areas decoded in Norman et al., 2021); task design → hemodynamic response function → ΔCBV(t) time series in the target. Blood speed field for the Doppler model.
- [ ] **Real-data skull path (optional):** load skull geometry from MUG500+ (meshes and segmentations) or HU volumes from CQ500, so procedural and real skulls share one interface.
- [ ] **Generative skull path (stretch):** SkullGAN (Naftchi-Ardebili et al., 2023) generates 2D skull CT slices; check whether weights are public and whether it can feed 2D imaging planes.
- [x] Sanity checks: layer thicknesses, property ranges and CT-vs-sound-speed R² checked against literature values; orthogonal-slice figures.

### Phase 2 — fUS sensor model *(Tue 17 – Wed 18 Nov)*
Output: per run, raw channel data (RF), beamformed IQ frames, a power Doppler image series, and the matching no-skull run.

- [x] **Imaging plane:** take a 2D plane through the 3D head under the probe (D-003). The probe position and angle are config parameters.
- [x] **Transducer:** 128-element linear array; centre frequency 2 MHz (sweep 1–3 MHz); pitch and element width set from wavelength; Gaussian-modulated pulse with set bandwidth; element directivity.
- [x] **Transmit sequence:** 7–11 plane waves over ±10°, coherent compounding; PRF and compounded frame rate set by imaging depth; Doppler ensemble length (e.g. a few hundred compounded frames per CBV image).
- [x] **Scatterers:** static tissue scatterers (speckle) plus moving blood scatterers whose number density follows CBV and which move with the blood speed field. Blood is a weak scatterer compared with tissue.
- [x] **Acoustic solver:** k-wave-python, pseudo-spectral, with heterogeneous c, ρ and power-law absorption (D-001). The same medium without the skull gives the paired clean run.
- [x] **Electronic noise:** additive, seeded, set by an SNR parameter.
- [x] **Processing chain:** delay-and-sum beamforming (assuming the brain's speed of sound, as a real scanner does), compounding, SVD clutter filter (Demené et al., 2015), power Doppler → CBV image.
- [ ] **Noise ablation switches:** each skull effect on or off on its own, for example a homogeneous skull with the same mean properties (no aberration), zero bone absorption (no attenuation), matched impedance (no reverberation).
  - *Built. Attenuation and reverberation switches have passing evals (E-DATA-006, E-FUS-006); the aberration switch does not (E-DATA-007 failing: homogenising the skull removes heterogeneity but not thickness-driven aberration).*
- [x] **Fast path (from the proposal):** precompute the skull operator once per element and angle, then synthesize the echoes for any blood configuration linearly (Born approximation). Check against the full simulation on a small case. Estimate memory before building.
- [x] Sanity checks: point-spread function in water against theory; arrival-time shifts through a homogeneous slab against analytic values; attenuation against α·f·d; activation recovered in the no-skull case.

### Phase 3 — CT scanner model *(Tue 17 – Wed 18 Nov)*

## 2. Design decisions

**D-001 — Acoustic solver: k-wave-python first, j-Wave as an option.** *Proposed, 16 Nov.*
The proposal names k-Wave, the standard for transcranial simulation, and k-wave-python ships a C++ OpenMP binary for Apple Silicon. j-Wave is a JAX port of k-Wave and is differentiable, which will matter later when the reconstruction needs gradients through the physics (raw-channel guidance). The solver sits behind one interface so we can switch.

**D-002 — One latent microstructure drives both CT and acoustics.** *Proposed, 16 Nov.*
If we set sound speed straight from HU, the CT would be a perfect prior and the main result would be meaningless. Instead, the ground truth is porosity plus composition, and both the X-ray attenuation and the acoustic properties are computed from it. A hidden component of sound speed is added that X-rays cannot see, tuned so CT explains 23–53% of sound-speed variance (Webb et al., 2018). The CT model then has to recover the skull through a realistic, imperfect measurement.

**D-003 — Anatomy in 3D, ultrasound in 2D planes.** *Proposed, 16 Nov.*
At 2 MHz a full-wave grid needs about 6 points per wavelength at the top of the band, roughly 0.08 mm spacing. A full 3D head at that spacing has on the order of 10⁹ voxels, which is not practical on a laptop (Apple M5 Pro, 24 GB). A 2D plane through the head, about 100 mm deep by 60 mm wide, is about 10⁶ grid points, which runs in seconds to minutes. A linear array also images a single plane, which is how real fUS works, and the proposal's simulation is 2D. The head stays 3D so that probe placement, out-of-plane skull shape and the CT are all real 3D objects. 3D acoustic runs on small cropped volumes are a later option.

**D-004 — Determinism through a seed tree.** *Proposed, 16 Nov.*
One root seed per run, split with `numpy.random.SeedSequence.spawn` into named streams: `anatomy`, `skull_microstructure`, `hidden_soundspeed`, `cbv`, `tissue_scatterers`, `blood_scatterers`, `us_electronic_noise`, `ct_photon_noise`. Changing one stream, for example the ultrasound noise, leaves every other part of the run bit-identical. Every output stores its config, its seed and the git commit.

**D-005 — Every noise effect is a switch.** *Proposed, 16 Nov.*
Aberration, attenuation, reverberation, tissue clutter, electronic noise and CT photon noise can each be turned on or off and scaled from the config. This allows clean ablations: how much of the image loss comes from each effect.

**D-006 — Three-tier forward model through a Green's bank.** *Proposed, 17 Nov.*
Everything a medium does to the sound field is stored once per skull as `B = G_medium / G_ref`, the one-way transfer function from each array element to each ROI point relative to a homogeneous reference at 1540 m/s. Three backends produce it behind one interface: `analytic` (water), `ray` (straight rays: delay, absorption, interface loss; seconds) and `kwave` (full wave; one simulation per element). This is the proposal's speed-up made concrete: the skull is simulated once, and any blood configuration is then synthesised linearly. Details in `docs/ARCHITECTURE.md` section 5.

**D-007 — Born approximation for blood and brain tissue; two data fidelities.** *Proposed, 17 Nov.*
Blood and brain-tissue scatterers are weak, so received signals are linear in them while the skull is treated exactly through the bank. `scatterer` fidelity moves explicit scatterers frame by frame (slow, physically explicit). `statistical` fidelity uses the fact that for random-phase blood the expected power Doppler image is linear in CBV, `E[PD] = H @ cbv` with `H = |A|^2`, plus gamma speckle and a noise floor (fast). E-FUS-014 checks the second against the first. `H` is also the image-domain forward model of the reconstruction.

**D-008 — Full-wave solver: k-wave-python 0.6.2, pure-Python backend, dispersion off, CFL 0.1.** *Proposed, 17 Nov. Supersedes the solver-binary part of D-001.*
k-wave-python 0.6.2 ships a NumPy solver, so no C++ binary is needed and the same code runs on Windows, macOS and Linux. Its dispersion term is switched off by default: with bone-like absorption at y = 1.1 it raises the simulated phase speed about 21 % above the sound-speed map, so the reference tier would not simulate the medium the head model describes (E-FUS-003, E-FUS-008). Default CFL is 0.1 because the k-space scheme has a phase error next to bone that grows with CFL^2. j-Wave is not wired in yet. Cost: about 300 core-hours for 128 elements at full resolution, so the `ray` backend is the workhorse and k-Wave is a small-scale reference.

**D-009 — PyTorch for the diffusion prior and the reconstruction.** *Decided by Sanketh, 17 Nov.*
Familiar, installs easily on Windows and macOS, runs on CPU. JAX (which would pair with j-Wave) was the alternative.

**D-010 — The paired clean run removes the skull in place.** *Proposed, 17 Nov.*
"Without the skull" means the same imaging plane with skull pixels given grey-matter acoustic properties (`head.ablations.remove_skull`). Geometry, scalp, CSF and brain are unchanged, so the clean and corrupted images are registered pixel for pixel.

**D-011 — Corrected beamforming is phase conjugation against a model bank.** *Proposed, 17 Nov.*
`das` takes a model `GreensBank`. The homogeneous bank gives conventional delay-and-sum at 1540 m/s. A ray bank through the CT-derived skull gives the "CT-derived delay correction" baseline; a ray bank through the true skull gives the "true-skull correction" baseline. The beamformer is normalised to unit scatterer gain under its model, so a correct model restores the peak by construction and pays in noise gain where the model field is weak. A plain average was the alternative; it leaves the corrected peak 1–3 dB low because phase conjugation cannot restore the transmit amplitude an aberrator removes. To confirm.

**D-012 — One global absorption exponent, y = 1.1.** *Proposed, 17 Nov.*
k-Wave's power-law absorption needs one exponent for the whole medium and is singular at y = 1. Absorption is stored as `alpha0` in dB/(cm MHz^y).

**D-013 — Blood scatterer model.** *Proposed, 17 Nov.*
Constant-magnitude scatterers with random signs (all-positive amplitudes make the mean density a coherent reflector), density proportional to CBV, moving on re-entrant straight paths so the density stays proportional to CBV, normalised so that `E[PD] = H @ (cbv * cell_area)` whatever the scatterer count.

**D-014 — Material constants: choices that need the team's confirmation.** *Proposed, 17 Nov.*
(a) Bone and pore densities follow NIST ICRU-44 (1920 and 1060 kg/m^3) instead of Aubry 2003 (2100 and 1000), so the acoustic density equals the mass the CT sees. (b) True skull absorption end points (1.4 and 11.2 dB/cm at 0.5 MHz) are fitted to the Aubry 2022 benchmark values; Aubry 2003's own 0.2 and 8 dB/mm would roughly double the skull loss. (c) The CT prior uses Aubry 2003's nominal map, so its absorption is about twice the truth: a deliberately imperfect prior, but the size of the error is a choice. (d) The hidden sound-speed component has a standard deviation of about 220–250 m/s at `porosity_r2 = 0.5`, because the porosity-driven variance is dominated by the table/diploë contrast; Webb 2018 measured across whole fragments, which is a different variance. (e) Water and air constants use a 20 °C reference state, not 37 °C.

**D-015 — The CT prior is scanned in a slab aligned with the imaging plane.** *Proposed, 17 Nov.*
The imaging plane is oblique to the head axes; scanning every axial slice it crosses would take tens of minutes. A thin slab aligned with the plane is scanned instead (physically a tilted-gantry acquisition), so the central CT slice is the imaging plane. Cost: the slab is an isolated block, so beam hardening and photon noise are weaker than in a full head scan.

**D-016 — Development scale.** *Proposed, 17 Nov.*
The head is generated as a box region around the probe (default 80 mm at 0.5 mm) rather than a full head (6.8e7 voxels, about 8 GB). Tests and evals use small grids. Full-resolution runs are launched by the user.

**D-017 — Noise level of the demo and where the signal sits.** *Proposed, 17 Nov.*
At 2 MHz the skull of the default head costs about 33 dB two-way. With the `fus` default electronic SNR (−10 dB, itself assumed) the uncorrected blood signal is about 35 dB under the noise floor, so nothing can be reconstructed by any method. The demo configs set 20 dB, which puts the transcranial blood signal a few dB under the floor: the regime in which the problem is hard but not hopeless. This single number decides whether the main result is achievable, so it should be tied to a measured transcranial sensitivity (for example coded-excitation gains) before any conclusion is drawn.

**D-018 — Known limit: the statistical tier's speckle is far too optimistic.** *Open, 17 Nov. Found in independent review; E-FUS-022 failing.*
The statistical fidelity draws each power Doppler pixel from a gamma distribution whose shape is the ensemble length (200 frames), as if every frame were an independent speckle realisation. Explicit moving blood gives about 1 independent frame at 1 mm/s and about 7 at 20 mm/s in a 100-frame ensemble, so the datasets carry 14 to 81 times too little speckle variance. Every dataset generated so far, and every reconstruction metric computed on them, is flattered by this. A starting formula that matched the measurements: `effective_frames ~ min(n_frames, 1 + duration * speed / (1.06 * PSF width along the flow))`, which gives roughly 1.5 to 11 for the default ensemble. To fix: set `doppler.effective_frames` per pixel from blood speed and ensemble duration, regenerate the datasets, and re-run the reconstruction experiment.

**D-019 — Known limit: the ray backend ignores refraction, and that matters at 2 MHz.** *Open, 17 Nov. Found in independent review; E-FUS-021 failing.*
Through a flat 6.5 mm slab at 2500 m/s the straight-ray travel time is later than the refracted first arrival by more than the project's lambda/14 budget for every element more than 9.4 mm off axis: 61 % of the default 128-element aperture, reaching 0.66 period at the edge, where the straight ray is beyond the critical angle. The ray backend generates all dataset banks and both correction baselines, so corrupted and corrected images are consistent with each other but not with a refracting skull. With the ray backend the "true-skull correction" baseline also uses the very model that generated the data. Options: a bent-ray (eikonal) travel-time backend; restricting the receive aperture to f-number 1.6 or more with the existing `beamforming.f_number` option; or generating reference banks with k-Wave on a cropped grid.

**D-020 — Scope of the determinism guarantee.** *Proposed, 17 Nov.*
"Byte-identical for the same config, seed and code version" is tested for one machine at one BLAS thread (E-DATA-003, E-COMMON-001). Different thread counts, BLAS libraries or CPU architectures can change the last bit of floating-point results, and thresholds can turn that into discrete differences, so bundle hashes should not be compared between the Windows machine and the Mac. Provenance now marks results produced from uncommitted code with a `-dirty` suffix.

**D-021 — `bent_ray` is the production backend.** *Decided while building, 17 Nov. Supersedes the open status of D-019.*
Dataset banks and both correction models (CT-derived and true-skull) now come from the `bent_ray` backend: refracted first-arrival travel times from an eikonal solver, absorption along the bent path, angle-dependent interface transmission and no energy beyond grazing. Narrowing the receive aperture to where straight rays are valid was the alternative; it was rejected because it discards real signal between about 17° and the critical angle near 38°. `ray` stays for fast tests and E-FUS-021 stays failing as the record of its limit. Remaining gaps against full-wave physics: only the first arrival is kept (no later arrivals, no reverberation), and the backend is checked against k-Wave only on homogeneous slabs at low frequency. With `bent_ray` the "true-skull correction" baseline still uses the very model that generated the data.

**D-022 — Speckle follows from blood motion.** *Decided while building, 17 Nov. Supersedes D-018.*
The statistical tier's speckle variance is derived per pixel from the local blood velocity, the resolution cell and the ensemble duration (`fus.speckle`), instead of assuming that all 200 frames of an ensemble are independent. In the demo scene a typical brain pixel then has 1.2 to 1.7 independent frames: one power Doppler image is close to a single speckle look. The information about activation therefore lies in averages over many images and many pixels, not in single images; the demo configs now acquire 120 images per scene. Known biases of the model, in both directions: velocities are uniform inside a resolution cell, which makes diffuse microvascular blood decorrelate too slowly (pessimistic); the clutter filter's removal of slow blood is not modelled (optimistic, and important at 2 MHz, where 1 mm/s is a Doppler shift of only about 2.6 Hz); the reconstruction is handed the true frame counts.

### 2026-11-17 — Speckle statistics of the statistical tier derived from blood motion (D-018)

### 2026-11-17 — Bent-ray (eikonal) Green's-bank backend (D-019)
- **What:** Added backend `bent_ray` behind `compute_bank` / `estimate_cost` (`BentRayConfig` nested in `BackendConfig`); `ray` is unchanged. Travel times come from a factored first-order eikonal solver in plain numpy (`fus/backends/eikonal.py`: batched line sweeps, one solve per element). The bank's delay is the slowness integral along the ray traced back through that field (`bent_ray_paths.py`). Amplitude is ray theory in a locally plane-layered medium (`bent_ray.py`): absorption along the refracted path, flux-normalised interface coefficients with the angle of incidence, spreading along the refracted ray, and a window that removes rays within 10° of grazing along the layers. `bank.meta` records the solver, grid spacing, post-critical fraction and a travel-time accuracy estimate.
- **Why:** D-019. Straight rays miss the refracted first arrival by up to 0.66 period at 2 MHz across the default aperture (E-FUS-021) and transmit at full amplitude beyond the critical angle.
- **Results:** Production case (128 elements, 35 x 33 ROI, 136 frequencies, 0.1 mm plane of the default head, seed 0): 36 to 39 s on one core, 354 MB peak, bit-identical across processes; `ray` takes 14 s. ### 2026-11-17 — Green's-bank backends (Phase 2, acoustic solver)
- **What:** Added `fus/backends` with `compute_bank` and `estimate_cost` behind one interface and three backends. `analytic`: the reference medium, B = 1. `ray`: straight rays with travel time, power-law absorption, flux-normalised interface transmission and a paraxial spreading factor; exposes `ray_travel_times`. `kwave`: k-wave-python 0.6.2 pure-Python solver, one simulation per element, referenced to the same solver in the homogeneous reference medium (shifted and mirrored across elements), direct DFT at the requested frequencies, and `static_fmc` from medium-minus-reference recordings at the array. ### 2026-11-17 — Ground-truth head package (Phase 1)
- **What:** Added `neurosim.head`: a procedural, seeded 3D head. Anatomy is a deformed-ellipsoid scalp with six strictly positive smooth thickness maps (radial signed-distance fields of the seven surfaces; skull about 6.5 mm at the vault and about 3.5 mm at the temporal windows; outer table, diploë, inner table). Skull porosity is a three-layer profile times a correlated texture. `hidden_c` is a bounded correlated field whose amplitude is solved per volume so that porosity explains `porosity_r2` (default 0.5) of skull sound-speed variance. `materials.py` derives sound speed, density, absorption (Aubry 2003 mixing law; soft tissue from the Aubry 2022 benchmark table) and CT basis-material fractions from `(labels, porosity, hidden_c)` only. CBV ground truth: grey/white baseline with a procedural vessel texture, a cortical activation patch, a blood velocity field, and a block design convolved with a double-gamma HRF. Plane sampling interpolates the latent fields and re-derives the acoustics. Four skull-effect ablations. HDF5 save/load with provenance, `scripts/generate_head.py`, `scripts/plot_head.py`, and default (80 mm box at 0.5 mm) and small (64 mm box at 2 mm) configs.
- **Why:** Phase 1; single source of truth for the ultrasound medium and the CT (D-002), with switchable skull effects (D-005).
- **Choices to confirm (see D-014):** bone and pore densities follow NIST ICRU-44 (1920 and 1060 kg/m^3, as the CT uses) instead of Aubry 2003 (2100 and 1000), so the acoustic density equals the mass the CT sees; absorption end points (1.4 and 11.2 dB/cm at 0.5 MHz) are fitted to the Aubry 2022 benchmark values, not Aubry 2003's 0.2 and 8 dB/mm; the hidden sound-speed component needed for `porosity_r2 = 0.5` has a standard deviation of about 220–250 m/s.
- **Limits:** `generate_head` returns `GeneratedHead` (a `HeadVolume` plus its material parameters). `sample_plane` rejects planes that leave the head volume; the default box holds a plane about 50 mm wide by 55 mm deep. The cortex is a smooth 2.5 mm shell without gyri, so the activation in a plane is a thin arc. Porosity, `hidden_c` and CBV textures are tied to the voxel grid (anatomy is not). The optional MUG500+, CQ500 and SkullGAN skull paths are not built.
- **Files:** `src/neurosim/head/{config,materials,fields,anatomy,microstructure,vasculature,cbv,generate,plane,ablations,io}.py`, `configs/head_default.yaml`, `configs/head_small.yaml`, `scripts/generate_head.py`, `scripts/plot_head.py`, `tests/unit/head/`, `evals/head/`.
- **Evals added (all passing):** E-HEAD-001 skull thickness and layer proportions; E-HEAD-002 property ranges; E-HEAD-003 porosity R^2; E-HEAD-004 plane resolution independence; E-HEAD-005 determinism and cbv-stream isolation; E-HEAD-006 ablation signatures; E-HEAD-007 X-ray/acoustic mass consistency; E-HEAD-008 grey/white CBV fractions; E-HEAD-009 task response against numerical convolution. E-HEAD-002 failed on its first run (skull sound speed 1499.9999 m/s from float32 rounding); fixed in code, threshold unchanged. Unit tests: 85 passing.
